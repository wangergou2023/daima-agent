# Bug 修复

针对代码 bug、构建失败、运行异常，采用最小修改和快速验证的修复流程。

## 何时使用
- 用户说“修一下这个问题 / 这个报错 / 这个 bug”
- 构建失败、运行失败、日志异常
- 某个工具或功能行为不符合预期

## 使用步骤
1. 先明确问题现象：错误日志、复现步骤、预期行为、实际行为。
2. 用 `search_files` 搜索：
   - 报错文本
   - 关键函数名
   - 相关配置宏
3. 用 `read_file` 分页读取最相关的 1-3 个文件，不要大面积盲读。
4. 优先做最小修改：
   - 单点逻辑修复优先 `edit_file`
   - 大块调整再用 `write_file`
5. 修改后立即验证：
   - 能编译就先编译
   - 能运行就做最短路径验证
   - 告诉用户“改了什么、为什么、怎么验证”

## 推荐排查顺序
- 先搜日志关键字
- 再搜函数名 / 宏名
- 再搜工具名 / 路径 / JSON 字段名
- 最后才扩大范围

## 注意事项
- 不要在还没定位主因前同时改很多文件。
- 如果只是工具轮次不够、提示词不稳、路径限制错误，优先修策略和边界条件。
- 回答里要明确：根因、改动点、验证结果。
