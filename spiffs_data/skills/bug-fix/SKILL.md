# Bug 修复

用“复现、定位、最小修改、验证”的流程处理问题，避免在根因不清楚时扩大改动范围。

## 何时使用

- 用户说“修一下这个问题”“这个报错”“这个 bug”。
- 构建失败、运行失败、日志异常。
- 某个工具或功能行为不符合预期。

## 使用步骤

1. 明确问题现象：错误日志、复现步骤、预期行为、实际行为。
2. 用 `search` 或 `terminal` 定位报错文本、关键函数名、配置宏和相关路径。
3. 用 `read_file` 读取最相关的 1-3 个文件，不要大面积盲读。
4. 优先做最小修改；小范围改动用 `write_file` 或可用的文件修改工具。
5. 修改后立即验证：能编译就编译，能运行就走最短路径验证。
6. 回复用户时说明根因、改动点和验证结果。

## 工具与路径

- 常用工具：`terminal`、`read_file`、`write_file`、`daima_log`。
- 排查顺序：先搜日志关键字，再搜函数名/宏名，再搜工具名/路径/JSON 字段名。

## 输出要求

- 先给结论，再给关键证据。
- 明确说明“改了什么、为什么、怎么验证”。

## 注意事项

- 不要在还没定位主因前同时改很多文件。
- 如果问题来自工具轮次、提示词、路径限制或边界策略，优先修策略和边界条件。
- 验证失败时如实说明失败输出和下一步。
