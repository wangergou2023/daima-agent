# 宠物导演

当用户正在 Web 聊天页面里调试、联动或展示右下角宠物时，你可以为宠物选择表达态。做法是在主聊天的最终回复末尾追加一个隐藏标记，前端会把标记去掉，不展示给用户。

## 何时使用
- 用户明确提到网页宠物、桌宠、右下角角色、状态切换
- 当前任务和宠物的情绪、动作、反馈联动有关
- 需要让宠物根据主聊天回复内容表达态度

## 使用步骤
1. 先正常完成你的文字回复，不要为了宠物牺牲回答质量。
2. 只在最终回复末尾追加一个隐藏标记，不要放在开头、中间，也不要输出多个。
3. 标记格式固定为：`[[pet:state=<state>]]`
4. `<state>` 只能从以下值里选一个：
   - `idle`
   - `runRight`
   - `runLeft`
   - `waving`
   - `jumping`
   - `failed`
   - `waiting`
   - `running`
   - `review`
5. 如果没必要表达特殊状态，就用 `idle` 或者不输出标记。

## 快速映射
- `idle`：普通结束、平静收尾、无需额外表演
- `review`：审查、分析、检查、排查
- `waving`：轻互动、友好回应、轻量完成感
- `jumping`：明显成功、庆祝、里程碑时刻
- `failed`：失败、受阻、缺资源、暂时做不到
- `running`：只有当你明确想强调“仍在推进中”时才用
- `waiting`：只有当你明确想强调“仍在等待外部条件”时才用
- `runRight` / `runLeft`：更偏表演态，只有用户明确想看方向动作时再用

## 职责边界
- Web 前端会自动控制过程态：
  - `running`：用户发出请求后，到最终回复返回前
  - `idle`：初始状态，以及用户 4 秒没有新输入时
- 你优先负责表达态：`review`、`waving`、`jumping`、`failed`
- 点击、拖拽、放下等独立宠物事件由后端 `pet` 通道处理，不归这个 skill 决定
- `runRight` 和 `runLeft` 更偏表演态，只有用户明确想玩动作效果或指定方向时再用

## 选择建议
- 普通回答结束：`idle`
- 正在继续处理、让用户稍等：`running`
- 审查代码、检查方案、分析问题：`review`
- 回答成功且想给一点互动感：`waving`
- 明显完成、突破、庆祝：`jumping`
- 执行失败、接口异常、缺资源：`failed`
- 网络未连上、结果未返回、等待外部条件：`waiting`

## 示例
- 普通收尾：`我已经改好了，刷新页面看看。[[pet:state=idle]]`
- 开心庆祝：`搞定，这次状态切换已经通了。[[pet:state=jumping]]`
- 代码审查：`我先把关键路径和边界条件过一遍。[[pet:state=review]]`
- 出错说明：`这个资源现在还没暴露给前端，所以暂时拿不到。[[pet:state=failed]]`

## 注意事项
- 不要输出多个 pet 标记。
- 不要在非 Web 宠物相关任务里滥用。
- 不要把 pet 标记放进代码块、列表项或引用块里。
- 先保证回答本身自然，再补宠物状态。
