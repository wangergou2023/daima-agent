# 项目进展追踪

把用户的口语化项目进展沉淀成可持续维护的周记录，并按需生成汇总、待办或周报。

## 何时使用

- 用户说“记录一下”“记一下进展”“今天进展”“更新某项目”。
- 用户要求“汇报一下进展”“项目汇总”“当前状态”。
- 用户要求“周报”“本周总结”“下周计划”。
- 用户提到多个项目的状态、阻塞、下一步、交付时间或客户反馈。

## 使用步骤

1. 获取当前日期和星期，使用用户时区 `Asia/Shanghai`。
2. 读取 `/spiffs/memory/PROGRESS.md`；不存在则创建。
3. 将“明天”“下周”等相对日期转成明确日期。
4. 找到当前周区块；没有则创建 `YYYY-Www (MM/DD - MM/DD)`。
5. 找到当天区块；没有则创建 `MM/DD 周X`。
6. 提取项目名、状态、关键事实、下一步、风险阻塞和截止日期。
7. 如果当天同一项目已存在，更新原条目，不重复追加。
8. 回复用户时先确认已记录，再给简短汇总。

## 工具与路径

- 常用工具：`get_current_time`、`files action=read`、`apply_patch`、`cron action=list`、`cron action=add`。
- 主记录：`/spiffs/memory/PROGRESS.md`。
- 长期偏好：`/spiffs/memory/MEMORY.md`。

## 输出要求

- 复杂多项目优先用 Markdown 表格。
- 当前进展表格建议列：项目、状态、关键、下一步。
- 周报必须基于 `/spiffs/memory/PROGRESS.md`，不要凭记忆补不存在的进展。

## 注意事项

- 不要把每日细节反复写入 `/spiffs/memory/MEMORY.md`。
- deadline 使用明确日期，不只写“明天”“下周”。
- 创建提醒时必须调用 cron 工具，不要只在文字里答应。
- 发现记录有截断或重复时，只修正本次相关条目，不做无关大清理。
