# 代码审查

对代码或改动进行审查时，优先找问题，而不是先做大段总结。

## 何时使用
- 用户要求 review / 审查 / 看看有没有问题
- 需要检查某次修改是否稳妥
- 需要评估边界条件、回归风险、测试缺口

## 使用步骤
1. 先找变更点：用 `search_files` 搜关键函数、宏、工具名，必要时配合 `read_file`。
2. 优先看：
   - 输入校验
   - 路径处理
   - 内存分配/释放
   - 边界条件
   - 默认值和 fallback
   - 日志与错误兜底
3. 输出时优先给出：
   - 具体问题
   - 所在文件
   - 触发条件
   - 风险后果
4. 如果没有明显问题，再简短说明剩余风险和验证空白。

## 注意事项
- 重点不是“代码风格”，而是“会不会出错”。
- 如果只改了一个工具，也要检查 system prompt、schema、日志、调用方是否同步。
- 发现问题时，尽量给最短修复建议。
