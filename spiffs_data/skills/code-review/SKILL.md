# 代码审查

对代码或改动进行审查时，优先找会导致 bug、回归、数据损坏或不可验证行为的问题。

## 何时使用

- 用户要求 review、审查、看看有没有问题。
- 需要检查某次修改是否稳妥。
- 需要评估边界条件、回归风险、测试缺口。

## 使用步骤

1. 先确认变更范围；必要时用 `terminal` 查看 git diff 或文件列表。
2. 用 `files action=read` 定点读取相关文件和调用方。
3. 优先检查输入校验、路径处理、内存生命周期、边界条件、默认值、错误兜底和日志。
4. 检查测试是否覆盖关键行为和失败路径。
5. 发现问题时给出触发条件、风险后果和最短修复建议。

## 工具与路径

- 常用工具：`terminal`、`files action=read`、`daima_log`。
- 如果涉及 skill 行为，也用 `skills action=list` 和 `skills action=view` 确认实际加载内容。

## 输出要求

- 有问题时按严重程度排序，先列问题。
- 每个问题尽量包含文件、位置、触发条件、风险和建议。
- 没有明显问题时，说明剩余风险和未验证点。

## 注意事项

- 重点不是代码风格，而是会不会出错。
- 如果只改了一个工具，也要检查 prompt、schema、日志和调用方是否同步。
- 不要用大段总结淹没关键风险。
