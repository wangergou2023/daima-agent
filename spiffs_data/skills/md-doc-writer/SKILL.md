# Markdown 文档

为代码仓库生成结构清晰、面向中文用户的 Markdown 文档。

## 何时使用

- 用户要求“总结一下，写成 md 文档”。
- 需要补 README、架构说明、迁移说明、功能概览。
- 需要把代码分析结果沉淀成长期可读文档。

## 使用步骤

1. 先按 `codebase-analysis` 思路建立结构认知。
2. 只读取和文档主题直接相关的关键文件。
3. 确定文档类型：功能概览、架构说明、迁移记录、使用说明或调试说明。
4. 先写提纲，再落正文，避免结构松散。
5. 生成文档时优先使用中文，术语保留英文原名并加反引号。

## 工具与路径

- 常用工具：`terminal`、`files action=read`、`apply_patch`。
- 常见输出：`README.md`、`docs/*.md`、迁移说明或调试说明。

## 输出要求

- 优先回答“这套东西是怎么工作的”。
- 可用结构：这是什么、核心能力、关键模块、主流程、重要配置、注意事项。

## 注意事项

- 不要简单把代码内容改写成逐文件说明。
- 如果用户准备移植功能，要写清依赖点、核心文件和最小迁移路径。
- 不要为了完整而读取无关文件。
