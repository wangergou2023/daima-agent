# Markdown 文档

为代码仓库生成结构清晰、面向中文用户的 Markdown 文档。

## 何时使用
- 用户要求“总结一下，写成 md 文档”
- 需要补 README、架构说明、迁移说明、功能概览
- 需要把代码分析结果沉淀成长期可读文档

## 使用步骤
1. 先用 `codebase-analysis` 的思路快速建立结构认知。
2. 只读取和文档主题直接相关的关键文件。
3. 确定文档类型：
   - 功能概览
   - 架构说明
   - 迁移记录
   - 使用说明
   - 调试说明
4. 先写提纲，再落正文，避免边读边写导致结构松散。
5. 生成文档时优先使用中文，术语保留英文原名并加反引号。

## 推荐结构
- `# 文档标题`
- `## 这是什么`
- `## 核心能力`
- `## 关键模块`
- `## 主流程`
- `## 重要配置`
- `## 最近改动 / 注意事项`

## 注意事项
- 不要简单把代码内容改写成逐文件说明。
- 要优先回答“这套东西是怎么工作的”。
- 用户如果准备移植功能，要特别写清依赖点、核心文件和最小迁移路径。
